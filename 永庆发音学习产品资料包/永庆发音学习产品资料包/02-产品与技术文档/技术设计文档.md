UniApp X + Vue 3 + UTS｜NestJS + TypeScript + MySQL｜MVP 架构

| **技术目标** 优先快速完成微信小程序 MVP，同时让后端可在未来用 Spring Boot 重写而不影响客户端和数据库。 |
|--------------------------------------------------------------------------------------------------------|

# 1. 技术栈

| **层级** | **选择**                      | **说明**                          |
|----------|-------------------------------|-----------------------------------|
| 客户端   | UniApp X + Vue 3 + UTS        | 微信小程序优先，保留 App 适配能力 |
| 状态管理 | Pinia                         | 用户、课程、播放、学习状态        |
| 服务端   | Node.js + TypeScript + NestJS | 模块化、Swagger、便于MVP          |
| ORM      | Prisma                        | 类型安全、迁移清晰                |
| 数据库   | MySQL 8                       | 关系明确，JSON字段承载音素映射    |
| 对象存储 | 腾讯云 COS                    | 标准音频、评测临时文件            |
| 音标     | CMUdict → IPA                 | 后台离线导入并版本化              |
| 发音     | 有道词典发音                  | 一次获取后缓存到COS               |
| 评测     | 腾讯云智聆口语评测            | 阶段2接入                         |
| 部署     | Docker Compose + Nginx        | 服务、MySQL、后续Redis            |

# 2. 总体架构

UniApp X 客户端只依赖版本化 REST API。NestJS
负责课程、词库、学习进度、音频代理与第三方服务编排；MySQL
保存业务数据；COS保存音频。第三方接口均由后端调用，客户端不保存密钥。

# 7. 音频处理链路

后台导入单词 → CMUdict 查询并转换 IPA → 调用有道词典发音 → 校验响应 →
上传 COS → 保存 audioUrl 与 source/version。用户播放时直接读取
COS/CDN，并使用长期缓存。

- 音频建议 MP3，短单词通常数 KB 到数十 KB；按需加载。

- URL 失效或资源缺失时由后端重新生成/补充，客户端只展示统一状态。

- 录音评测文件设置生命周期自动清理；明确隐私提示和删除策略。

# 9. 设计实现规范

- 设计基准宽度390；使用rpx/自适应布局，不按截图绝对定位。

- 颜色：背景#F7F8FC、正文#14213D、主色#5267F8、成功#21A66B、边框#E8EBF2。

- 字体：系统字体，优先 PingFang SC；标题24/22/17，正文14，辅助12。

- 间距使用8px体系；卡片圆角16-18；点击热区至少44px。

- 通用图标使用Iconify/Lucide对应SVG；定制图形从本资料包直接引用。

# 10. 安全与可靠性

- 有道、COS、腾讯云密钥仅存服务端环境变量。

- 上传文件校验格式、大小和时长，生成不可预测对象键。

- 接口限流；评测与音频生成任务幂等。

- 日志不记录完整Token、密钥和原始录音地址。

- 数据库迁移纳入版本控制，生产环境定期备份。
